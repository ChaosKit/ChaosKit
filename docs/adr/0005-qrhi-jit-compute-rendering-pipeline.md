# GPU Rendering via Qt RHI, Runtime GLSL JIT, and Compute Scatter Accumulation

Both the interactive UI (`ui/`, via `QQuickRhiItem`) and headless CLI (`cli/`, via swapchain-free `QRhi::beginOffscreenFrame()`) share an end-to-end GPU-resident **Rendering** pipeline built on Qt 6 `QRhi` (`GPLv3`), replacing the forced OpenGL 3.2 Core path (which lacks compute shaders on macOS, where OpenGL is frozen at 4.1) while keeping `ast/`, `core/`, and `library/` Qt-free (`Apache 2.0`) and retaining the CPU engine as a reference and fallback (`--backend auto|gpu|cpu`). A Qt-free C++ compiler lowers the authored **System** and **Camera** AST into straight-line Vulkan-flavored GLSL compute shaders compiled at runtime via `QShaderBaker` (`Qt6::ShaderToolsPrivate`), with all numeric parameters, **Blend** and **Formula** weights, and **Lifetime** packed into uniform buffers so continuous edits never recompile shaders. **Accumulation** runs as pure in-register compute dispatches (with C++-faithful math helpers, immediate revival of non-finite **Particles**, and a counter-based PRNG for deterministic `--seed`) that sample a `1024 × 1` `RGBA32F` **Color Map** LUT texture and scatter hits into a GPU **Histogram** storage buffer using lock-free 64-bit carry-pair (`2 × uint32`) fixed-point `atomicAdd`, avoiding both floating-point atomic portability limits and Apple Silicon TBDR point-rasterization bottlenecks. Finally, **Tone Mapping** normalizes accumulated **Histogram** sums by `currentIpp / 100.0` (**Iterations Per Pixel** relative to `chaoskit-render`'s `100` IPP baseline) so progressive **Rendering** maintains constant brightness from the first frame through deep or infinite **Accumulation** without overexposing, while preserving backward compatibility with existing **Project** `exposure` values and golden images.
